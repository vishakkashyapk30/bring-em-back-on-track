# Runbook

## Prerequisites

- Linux/macOS, ~20 GB free disk (dataset ~10 GB unzipped + images)
- Docker 24+ with Compose v2 (container path), **or** Python 3.12 via [`uv`](https://docs.astral.sh/uv/) and Node 20 (local path)

## 1. Get the data

```bash
mkdir -p data/raw && cd data/raw
uvx --from 'huggingface_hub[cli]' hf download nuxsh/maple-collections-hackathon \
    maple_collections_release.zip README.md --repo-type dataset --local-dir .
unzip -q maple_collections_release.zip        # -> data/raw/maple_collections_release/
# optional voice pack (2.4 GB): download maple_collections_voice.zip, unzip, copy its files/ into maple_collections_release/
cd ../..
```

Read `data/raw/maple_collections_release/README.md` (conventions: only empty string is null, `NA` is a real code, identifiers as text with leading zeros, Hive-partitioned Parquet). The zip can be deleted after unzipping to save 2.3 GB.

## 2a. Run with Docker (recommended for the demo)

```bash
docker compose up --build   # the whole system on http://localhost:8080
```

That one command builds the images, then a one-off `bootstrap` container downloads the dataset into `./data/raw` if it isn't there, builds the warehouse on the first run (about 5 minutes: ingest, silver, identity, gold + contract tests, features, quality report, benchmark), and exits. The API starts once it succeeds and the web once the API is healthy. Later runs find the data and start in seconds. `REBUILD=1 docker compose up --build` rebuilds the warehouse; `make test-containers` runs the tests in the image; `docker compose down` stops it.



## 2b. Run locally

```bash
cp .env.example .env
make setup               # uv sync + npm install (make setup-rag adds lancedb + fastembed)
make data                # bronze → silver → identity → gold → features
make train && make score
make api                 # terminal 1, :8000
make web                 # terminal 2, http://localhost:5173
make test && make lint
```

## Troubleshooting

| Symptom | Fix |
|---|---|
| DuckDB out of memory on large tables | Lower `C360_DUCKDB_MEMORY` in `.env`; the Parquet tables are partitioned by year |
| API says `warehouse: false` on `/api/health` | No warehouse published yet: run `make nightly` (or `make data`) |
| `npm` engine warnings | Node 20 is pinned for; jsdom/jest-dom are pinned to Node-20-compatible versions |
| Port 8080 in use | `WEB_PORT=8090 make up` |
| LLM features show "offline" | Expected: offline is the default (D13). Set `LLM_PROVIDER` and keys in `.env` to try a provider |

## The 19:00 benchmark run (4 Oct)

At 19:00 IST the organisers release extra benchmark questions. The submission CSV must include them, produced by the system as it is, with no hand edits.

1. Save the released file somewhere, for example `~/Downloads/extra_questions.csv`. It should have the same columns as `benchmark_questions.csv`; the runner also accepts `;` or tab delimiters, a BOM, and `id` or `question` as column names. Ids already answered are skipped, so running it twice is safe.
2. Run it (about 1 minute for 40 questions; add `LLM_PROVIDER=ollama` to use the language model, see below):

   ```bash
   uv run python -m eval.run_benchmark --questions ~/Downloads/extra_questions.csv
   ```

3. The answers are written to `deliverables/benchmark_answers.csv` (columns `question_id, answer, sql_or_sources, refused`) and a run summary to `reports/benchmark.json`. One question that fails is answered as a refusal instead of stopping the run.
4. Read the new rows. If a number answer looks wrong, fix the system (the metric registry in `semantic/registry.py` or the refusal rules in `nlq/refusal.py`), add the question to `eval/probe/questions.csv`, and rerun. Do not edit the CSV by hand.
5. Commit the CSV before 21:00.

Rehearsed on 4 Oct with a semicolon-delimited file, a column named `question`, a duplicate id and a request for national IDs: all handled.

## Language model for Ask (optional)

The default is `LLM_PROVIDER=offline`: rules and templates only, no network, the same answer every time, and it is what a judge gets from `docker compose up --build`. A language model can be switched on for questions the rules do not recognise:

| Setting | How |
|---|---|
| Local, free | `ollama pull mistral`, then put `LLM_PROVIDER=ollama` and `OLLAMA_MODEL=mistral:latest` in `.env`. In Docker the API reaches the host's Ollama through `host.docker.internal`. |
| Free cloud | A Google AI Studio key: `LLM_PROVIDER=gemini`, `GEMINI_API_KEY=...`, `GEMINI_MODEL=...`, and `uv sync --extra llm`. Not tested yet (no key). |

What the model may do, and nothing else:

- **Pick a certified metric** for a question the rules did not recognise. It chooses from a closed list; the breakdown, filters and period are read by the rules; the SQL is generated by the compiler and passes the same guard. A pick is thrown away if it shares no meaningful word with the question, or if the question asks for something unmeasurable (forecast, handle time, revenue). The answer says that a model matched the metric.
- **Word a policy answer** from the top retrieved sections. Every citation must be a retrieved section and every quote must appear word for word in it, or the extractive answer is used instead.
- It never writes SQL, never sees customer rows, never decides eligibility, and cannot override a refusal rule.

Measured with `LLM_PROVIDER=ollama OLLAMA_MODEL=<model> uv run python -m eval.llm_rewrite_eval <model>` on 24 questions that are not in the benchmark (15 paraphrases of certified metrics, 9 that must be declined):

| Model | Mapped to the right metric | Declined correctly | Wrong metric given |
|---|---|---|---|
| Rules only (no model) | 5 of 15 | 9 of 9 (after a fix: a forecast question was being answered) | 0 |
| mistral 7B | 12 of 15 | 9 of 9 | 2 |
| gemma3 4B | 11 of 15 | 9 of 9 | 3 |
| llama3.2 3B | 4 of 15 | 9 of 9 | 0 |

The wrong picks are neighbouring metrics (promise-taken rate against promise-kept rate, cost per contact against cost per right-party contact). A small local model is a help, not a judge; a stronger cloud model should do better, which is why the Gemini option exists.
